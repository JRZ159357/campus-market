## 2. 角色模型（4 级，无游客）

| 角色码 | 名称 | 获得方式 | 核心权限 |
|---|---|---|---|
| `user` | 普通用户 | 微信登录自动获得；或账号密码注册 | 浏览、搜索、下单、收藏、评价；**不可发布商品** |
| `student` | 认证学生 | 普通用户提交学号+姓名+学生证照片，管理员审核通过 | 普通用户全部 + 学生徽章 + 优先推荐 + 发布商品（同时上限 20 件） |
| `customer_service` | 客服 | 管理员后台分配 | **只读**为主：可查看用户、商品、认证、订单、举报；**举报的接单与处理是可写的本职权限**（`/api/report/admin/**`）；其余新增/修改/删除/审核一律不可 |
| `admin` | 管理员 | 初始化/管理员分配 | 全部权限 |

**关键业务规则**：
- `user → student` 是唯一可自助申请的升级路径；`customer_service` / `admin` 只能由管理员分配，不开放注册。
- 发布商品接口必须校验 `role == student`。
- 全部角色（含普通用户）都有 `username + password`，支持账号密码登录；微信用户可在个人中心绑定账号密码，绑定后两种方式登录同一账号。
- 客服为**只读角色**：拦截器对所有非 GET 请求返回 403，前端同步隐藏写操作入口。**唯一例外**是举报接单与处理（前缀 `/api/report/admin/`）—— 接单和处理就是客服的工作，一刀切会让工单系统停摆，还会诱使线下借用管理员账号。

## 4. 全局技术约定

- 统一返回体 `Result<T>`：成功 `code=200`，失败 `code=500`，参数错误 400，未登录 401，无权限 403。
- 接口路径 `/api/{模块}/{操作}`，动词由 HTTP 方法表达。
- 分页参数固定 `pageNum` / `pageSize`，返回 `records/total/current/size`；瀑布流另提供游标分页 `cursor`，返回 `records/nextCursor/hasMore`。
- 时间格式 `yyyy-MM-dd HH:mm:ss`，时区 `Asia/Shanghai`。
- 逻辑删除字段 `deleted`（0/1）。
- 鉴权：JWT 只携带 `userId`，**角色与状态从 Redis 缓存/数据库读取**（保证角色变更、封禁立即生效）；token 存 Redis 白名单，支持强制下线。
- 登录方式：微信登录与账号密码登录签发同一套 token；账号 4-20 位字母数字，全表唯一。
- 权限：客服只读（仅 GET 放行，白名单：登录/登出/个人信息/绑定账号/改密；**写前缀白名单：`/api/report/admin/`**），管理员全部放行。前缀只解决路径变量匹配，授权边界仍在 `@RequireRole`。
- 密码：BCrypt，禁止明文；预置账号 admin / service01 / service02，初始密码 123456。
